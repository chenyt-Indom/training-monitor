终端里实时盯 YOLO 训练：每轮指标、趋势箭头、ASCII 曲线、ETA、过拟合判断。
不用等训练跑完再去看 `results.png`，也不依赖 TensorBoard。

## 它解决什么问题

ultralytics 训练过程中只有一行不断刷新的进度条，真正的每轮指标要等
`results.csv` 写出来才能看。这个脚本把那份 CSV 读成一张**能一眼看出趋势**的表：

- 哪一轮是当前最佳（🏆）
- mAP 是在涨、在平、还是在跌（▲▲▲ / ▬ / ▼▼▼）
- 现在离训完还有多久（用历史每轮耗时推算，不是拿总时长瞎猜）
- 当前这一轮跑到第几步了（总进度 + 本轮进度，两条进度条）
- 是不是已经开始过拟合（连续 5 轮下降且跌幅超过 2% 会直接报警）

它只**读文件**，不碰训练进程。随便 Ctrl+C 退出，训练照常跑。

## 安装

只需要 Python 3.9+，标准库就够。两个可选依赖：

```bash
pip install psutil        # 想在监控里看到内存占用就装
# nvidia-smi 来自显卡驱动，装了 CUDA 驱动就有，用来显示 GPU 利用率和显存
```

把 `monitor.py` 拷到任意位置即可，没有其他文件依赖。

## 用法

```bash
# 自动探测 ./runs/detect、./runs/segment、./runs/pose 等常见位置
python monitor.py

# 训练输出不在默认位置，指定根目录（可重复写多次）
python monitor.py --runs-dir D:/fire_runs

# 直接盯某一个具体的 run 目录
python monitor.py --runs-dir D:/fire_runs/fire_smoke_v7_26s960

# 只输出一次快照，适合丢进日志或 CI
python monitor.py --runs-dir D:/fire_runs --once

# 5 秒刷新一次；终端编不出 emoji 时强制 ASCII
python monitor.py --interval 5 --ascii
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--runs-dir DIR` | 自动探测 | 训练输出根目录，可重复指定；也可直接指向某个 run 目录 |
| `--interval SEC` | `3` | 刷新间隔 |
| `--once` | 关 | 只输出一次就退出 |
| `--no-clear` | 关 | 不清屏，每次刷新追加输出 |
| `--ascii` | 自动判断 | 强制用 `#` `-` `*` 这类纯 ASCII 符号 |
| `--width N` | `94` | 分隔线与曲线宽度 |

## 它是怎么找到训练的

三层来源，任一可用即可：

1. **results.csv** —— 每轮指标的唯一权威来源，表格和曲线都读它
2. **args.yaml** —— 取 epochs / batch / imgsz / lr0 / patience 显示在表头
3. **训练日志** —— 仅在 `results.csv` 还不存在时启用。只读文件末尾 8KB，
   用正则从进度条里提取 epoch / 步数 / it·s⁻¹ / 本轮剩余时间

「最新的一次训练」按 `results.csv` 的修改时间排序，没有该文件则退回目录修改时间。
这一点很关键：否则刚启动的训练会被判成 0 分，监控就停在几个月前的旧任务上不动了。

另外只有带 `weights/` 子目录的才会被认成训练目录，基准测试、标定、半途失败的
临时目录都会被自动排除。

## 常见问题

**中文或 emoji 显示成乱码 / 直接报 UnicodeEncodeError**

Windows 的 `cmd` 默认代码页是 936（GBK），编不出 `█ ▲ 🏆`。两种解法：

```bat
chcp 65001
set PYTHONIOENCODING=utf-8
python monitor.py --runs-dir D:/fire_runs
```

或者直接加 `--ascii`，脚本会自动换成 `# - *` 那套符号，中文照常显示。

**显示「未找到训练目录」**

脚本默认只找当前工作目录下的 `runs/*`。训练输出在别处就得用
`--runs-dir` 指过去。也可以写进配置文件，省得每次敲：

```json
// ~/.yolo_monitor.json
{ "runs_dirs": ["D:/fire_runs", "E:/experiments"] }
```

**监控会不会拖慢训练**

不会。只做文件读取和 `nvidia-smi` 查询，不 import torch，不占显存。
读日志时也只 seek 到末尾读 8KB，不会把几百 MB 的日志整个读进内存。
